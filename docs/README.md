# Unified Demo Branch Notes

The `demo` branch is the single Binary SDK consumer branch. It does not contain Bridge implementation source.

## Projects

```text
OcctDemo.Common
├─ OcctDemo.WinForms  → OcctNet.WinForms   (Windows x64)
├─ OcctDemo.Wpf       → OcctNet.Wpf        (Windows x64)
└─ OcctDemo.Avalonia  → OcctNet.Avalonia   (Windows x64 / Linux x64)
```

All three UI applications share modeling, commands, history and scenarios from `OcctDemo.Common`. Windows validation is completed first; Linux Avalonia build/run/publish scripts are integrated and validated afterward in this same branch.

## Bridge 3 / ABI5 consumer boundary

The Demo consumes only the validated Binary SDK generated by `main`.

- No `src/OcctNative` or `src/OcctNet*` implementation source is tracked here.
- Demo C# code must not declare or call `occt_*` Native ABI entry points.
- Pre-ABI5 generic handles and compatibility metadata are forbidden.
- Retired object snapshot, appearance alias, Viewer BRep annotation and old Modeling-to-Viewer APIs are rejected by `tests/check-sdk-consumer.ps1`.
- Current public APIs such as the global View `SetDisplayMode`, object-level `SetObjectDisplayMode`, and Headless Modeling `Exists` remain valid and must not be blocked by compatibility checks.

## Binary SDK workflow

`dist/` is intentionally ignored by Git and is not a second source of truth.

On Windows:

```powershell
.\sync.ps1
```

`sync.ps1` validates contract schema 3, manifest schema 2, ABI5-only metadata, target frameworks, .NET SDK 10.0.303, C# 14 and SDK file hashes. It reuses `dist/win-x64` when `manifest.sourceCommit` already matches `origin/main`; use `-ForceRebuild` only when a clean regeneration is required.

The clean source worktree used for SDK regeneration is created beside the repository rather than under `%TEMP%`, avoiding MSBuild temporary-directory output warnings.

## Current platform phase

Windows x64 currently owns the active validation gate:

```powershell
.\build.ps1 validate Release
.\build.ps1 all Release
```

After WinForms, WPF and Avalonia pass Windows build/run/publish validation, the remaining Linux Avalonia scripts are migrated from the legacy Avalonia branches into `demo` and validated there. The standalone Avalonia branches can then be removed.

No GitHub Actions or NuGet publication flow is used by this demo branch.
