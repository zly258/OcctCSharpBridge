# 08 构建测试与发布

`build.ps1` 是 `main` 的统一本地入口。验证按三层组织：**仓库级静态契约 → Managed 回归 → 真实 Native Smoke**。原则是让每类问题由最可靠的机制验证，而不是用大量 PowerShell 字符串扫描替代编译和测试。

## 1. `bridge-contract.json`

机器可读契约包括：Bridge Version、Native ABI Version、OCCT Version、平台、CMake Minimum Version、Target Framework、.NET SDK、C# Language Version 和 API 数量。

当前 Contract 为 Bridge `2.6.0`、Native ABI `4`、OCCT `7.9.0`、Native/PInvoke `344/344`、Viewer/Modeling `210/134`。代码和构建配置必须与 Contract 一致；README/docs 只负责说明，不作为构建配置的第二份来源。

## 2. 本地 build target

```powershell
.\build.ps1 validate Release
```

只执行仓库级静态契约，不需要 OCCT SDK。

```powershell
.\build.ps1 managed Release
```

增量构建 `OcctNet`、WinForms/WPF/Avalonia Host。默认保留各项目 `bin/obj`，由 MSBuild 判断是否需要重新编译。

```powershell
.\build.ps1 test Release
```

构建 `OcctNet.ManagedTests` 并通过标准 `dotnet test` 执行 Managed Regression，不加载 OCCT Native Runtime。仓库固定使用 .NET 10，根目录 `global.json` 通过 `test.runner = Microsoft.Testing.Platform` 明确选择 Microsoft Testing Platform，避免回落到不再受支持的 VSTest Target。

```powershell
.\build.ps1 native Release
```

使用 CMake + MSVC + OCCT 7.9.0 构建 `OcctNative.dll`。

```powershell
.\build.ps1 pack Release
```

构建四个 Managed NuGet/Symbol Package，并检查包内程序集、XML、README/LICENSE 以及 Native Runtime 泄漏。

```powershell
.\build.ps1 ci Release
```

这是本地聚合目标名称，执行 Managed SDK、Managed Regression、Smoke Project 编译和 NuGet 验证；它不是 GitHub Actions，也不访问远程 CI 服务。

```powershell
.\build.ps1 smoke Release
```

构建真实 Native Bridge 与 Smoke 项目，将 `OcctNative.dll` 放到 Smoke 输出目录，并在启动 Smoke 子进程时显式传入解析后的 `OCCT_ROOT`。`OcctRuntime` 会在首次加载 Bridge 前把 OCCT `win64/vc14/bin` 与 `3rdparty-vc14-64` 下的运行时目录注册到 Windows DLL 搜索路径，因此无需把整套 OCCT/第三方 DLL 平铺复制到测试目录。

```powershell
.\build.ps1 clean Release
```

显式删除 `build/`、`artifacts/` 以及各项目 `bin/obj`。只在真正全量重建、切换异常缓存或排查生成文件问题时使用。

```powershell
.\build.ps1 all Release
```

执行静态契约后构建 Native + 四个 Managed SDK 项目。Managed Test 和 Native Smoke 仍是独立门禁，不隐式混入 `all`。

## 3. 不使用 GitHub Actions

仓库不依赖 `.github/workflows` 进行构建、测试、API 校验或 `main/demo` 同步。验证统一回实际开发环境：

- C# / SDK：本地 `.NET 10.0.302`；
- Native：本地 MSVC + OCCT 7.9.0；
- Runtime：真实 `OcctNative.dll` + 显式 `OCCT_ROOT`；
- 分支同步：维护者显式比较并同步共享层。

这样不会出现云端校验通过但本机 OCCT/MSVC 组合仍无法编译的假象。

## 4. 默认使用增量构建

日常构建保留 `bin/obj`：

- `managed` / `all` / `ci` 让 MSBuild 正常使用 Inputs/Outputs；
- `pack` 在已完成构建后使用 `--no-build`；
- Managed Test 在测试程序集已构建后使用 `dotnet test --no-build`；
- 真正需要清理时统一执行 `build.ps1 clean`。

不要在每个项目构建前递归删除 `bin/obj`，否则会把正常增量构建退化成多次局部全量构建。

## 5. 静态契约

当前只保留 6 个脚本：

| Script | 检查范围 |
|---|---|
| `check-version-contract.ps1` | Contract 与 Native/Managed/.NET/CMake 版本和平台，同时验证 .NET 10 MTP Runner |
| `check-architecture-boundaries.ps1` | Core/UI 依赖方向、main/应用层边界、禁止兼容层 |
| `check-bulk-abi.ps1` | Modeling 高数量集合与 Selection Hit 的 Bulk ABI |
| `check-native-build-structure.ps1` | CMake 源清单、OCCT 7.9 Toolkit、禁止 OCAF/XDE |
| `check-api-surface.ps1` | Native declaration/definition/PInvoke 对等与数量 |
| `check-sdk-package.ps1` | Managed SDK NuGet 元数据 |

适合静态检查的是长期仓库不变量，例如 ABI 对等、API 数量、OCAF/XDE、CMake 漏列源文件、项目边界和 Package Metadata。

以下内容不再用固定字符串扫描强制：方法必须位于哪个 partial 文件、某个实现必须逐字包含某段源码、README 必须包含固定句子、源文件最大字节数等。它们应由编译、测试或代码评审验证。

## 6. Managed Regression

Managed Regression 使用 `MSTest.Sdk` + Microsoft Testing Platform，不加载 OCCT，覆盖：

- Value Type / Guard；
- Owner-aware Handle；
- Geometry/Transform Helper；
- Runtime Diagnostics 无副作用；
- Viewport Interaction Policy；
- Native DTO ↔ Managed Result Mapping。

测试采用标准 `[TestClass]` / `[TestMethod]`，由 `dotnet test` 和 Visual Studio Test Explorer 正常发现。

## 7. Native Smoke

只有真实 OCCT Smoke 才能验证：

- C++ 编译和链接；
- `OcctNative.dll` / OCCT DLL / 第三方 DLL 加载；
- 实际几何和拓扑算法；
- Viewer/Selection Native 行为；
- Mesh 和数据交换；
- ABI Struct 在真实调用中的正确性。

发布前执行：

```powershell
.\build.ps1 smoke Release -OcctRoot "D:\tools\occt-vc144-64"
```

Smoke 启动前应满足：

- Smoke 输出目录存在 `OcctNative.dll`；
- `OCCT_ROOT` 指向有效 OCCT 7.9.0 根目录；
- `$OCCT_ROOT\win64\vc14\bin\TKernel.dll` 存在；
- 第三方 Runtime 位于 `$OCCT_ROOT\3rdparty-vc14-64` 的标准 `bin` 目录结构中。

`OcctRuntime` 会通过 `AddDllDirectory`/PATH 注册这些依赖目录。若仍出现 Win32 126，应检查缺失的具体依赖或第三方目录布局，而不是继续复制更多 DLL 到仓库输出目录。

## 8. API 数量不是完整 ABI 校验

当前 `344 Native == 344 P/Invoke` 能发现新增/删除遗漏，但不能发现：

- `double` → `float`；
- 参数顺序变化；
- `int64` → `int32`；
- Struct 字段布局变化；
- Enum 数值变化。

后续 ABI 强化应增加签名级检查：Return Type、Parameter Type/Order、Struct `sizeof/offsetof`、Enum Numeric Value。这个方向比继续新增源码字符串 Contract 更有价值。

## 9. 推荐验证顺序

日常 Managed 修改：

```powershell
.\build.ps1 validate Release
.\build.ps1 managed Release
.\build.ps1 test Release
```

涉及 Native / ABI / OCCT：

```powershell
.\build.ps1 all Release
.\build.ps1 smoke Release
```

准备 SDK 包：

```powershell
.\build.ps1 pack Release
```

## 10. `main` / `demo` 同步

共享实现由维护者手工同步；不要通过自动工作流覆盖分支。共享范围和分支专属范围见 [02 架构与边界](02_架构与边界.md)。同步前后都应在目标分支运行对应本地构建。

## 11. 新增检查原则

新增 PowerShell Contract Check 前必须同时满足：

1. 属于长期仓库不变量；
2. 编译或运行测试不能更可靠地验证；
3. 正常内部重构不会触发误报；
4. 与已有检查没有重复职责。

否则优先补 Managed Test、Native Smoke 或 ABI 自动校验。
