# 快速开始

OcctCSharpBridge 3.0 Stable 的官方预编译交付平台是 **Windows x64**。Linux x64 保留源码构建、Core 和 Avalonia 运行支持，但 3.x Release 不提供官方 Linux 预编译 SDK。

## 1. 当前契约

- Bridge：`3.0.0`
- Native ABI：仅 ABI 5
- OCCT：7.9.0 exact
- Windows 官方预编译：x64
- Linux：源码构建支持
- Binary SDK 最低 TFM：`net8.0` / `net8.0-windows`
- Consumer：.NET 8 / 9 / 10
- WinForms/WPF：Windows
- Avalonia：Windows；Linux 源码构建

Bridge 源码使用稳定版 .NET 10 SDK 构建，基线 `10.0.100`，`rollForward=latestFeature`。

## 2. Windows 应该使用哪一种产物

### Binary SDK

用于编译引用和 Contract/Manifest/Hash 校验：

```text
dist/win-x64/
  OcctNative.dll
  OcctNet.dll
  OcctNet.WinForms.dll
  OcctNet.Wpf.dll
  OcctNet.Avalonia.dll
  bridge-contract.json
  bridge-manifest.json
```

### Portable SDK

用于正式 Windows 部署：

```text
OcctCSharpBridge-<version>-win-x64-portable/
  OcctNet*.dll
  runtime/
  occt/resources/
  bridge-contract.json
  bridge-manifest.json
  package-manifest.json
  licenses / notices
```

正式第三方项目优先消费 `main` 对应的 Windows Release Asset。完整规则见 [第三方项目消费 SDK](09_第三方项目消费SDK.md)。

## 3. 引用 Managed 程序集

Headless/Core：

```xml
<ItemGroup>
  <Reference Include="OcctNet">
    <HintPath>$(OcctBridgeSdkRoot)\OcctNet.dll</HintPath>
    <Private>true</Private>
  </Reference>
</ItemGroup>
```

按需要增加：

```text
OcctNet.WinForms.dll
OcctNet.Wpf.dll
OcctNet.Avalonia.dll
```

项目可以使用 .NET 8、9 或 10；不需要为三个 Runtime 准备三套 Bridge Managed DLL。

## 4. Runtime 初始化

Portable SDK 部署时：

```csharp
using OcctNet;

OcctRuntime.Configure();

using var model = new OcctModelingSession();
var box = model.MakeBox(100, 80, 10);
model.ExportStep(box, "box.step");
```

`OcctRuntime.Configure()` 应早于第一个 `OcctEngine`、`OcctModelingSession` 或其它 Native-backed 调用。

Managed DLL、`runtime/`、`occt/resources/` 和 Manifest 必须来自同一个 Bridge Build / `sourceCommit`。

## 5. 没有正式 Release Asset 时

从一个明确的正式 `main` 提交快速生成 Consumer SDK：

```powershell
.\build.ps1 dist Release `
  -OcctRoot "D:\tools\occt-vc144-64"
```

需要部署 Runtime Closure 时再调用 Windows Portable Packager。`dist` 不执行 ManagedTests、Consumer Matrix、Core Smoke 或窗口 Smoke，这是设计上的 Consumer 快路径。

Bridge 维护者的正式 Stable 验证使用：

```powershell
.\tools\validate-stable-release.ps1 `
  -OcctRoot "D:\tools\occt-vc144-64"
```

## 6. Linux

Linux 使用者从源码构建：

```bash
./build.sh validate Release
./build.sh all Release
```

图形环境下验证 Avalonia：

```bash
./build.sh avalonia-smoke Release
```

Linux 自行构建的 Native Binary 应与目标发行版、OCCT 7.9.0 和 C/C++ Runtime 环境匹配。
