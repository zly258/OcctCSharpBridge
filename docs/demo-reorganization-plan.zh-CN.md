# Demo 分支重整计划

## 目标与边界

- Demo 只作为已安装 Bridge SDK 的 Consumer，不复制、同步或引用 `main` 的 Bridge 源码工程。
- WPF、WinForms、Avalonia 使用同一套功能分类、菜单顺序、命名和默认设置。
- UI 只负责平台适配；命令定义、功能语义和状态规则放在 `OcctDemo.Common`。
- 所有 Bridge 接口必须使用编译期可检查的强类型调用。禁止反射、`dynamic`、字符串方法名分发和 `DynamicInvoke`。
- SDK 的构建、校验、Portable Runtime 打包和安装全部属于 Bridge `main`；Demo 不维护第二套 SDK 生命周期。

## 信息架构

| 一级菜单 | 职责 | 主要内容 |
|---|---|---|
| 文件 | 文档生命周期和交换 | 新建、打开、保存、导入、导出、退出 |
| 编辑 | 已有对象操作 | 撤销、重做、变换、删除、选择、可见性 |
| 创建 | 新建几何与标注 | 曲线、基本体、特征、布尔、标注 |
| 检查 | 模型查询 | 包围盒、质量属性、拓扑、距离、有效性 |
| 视图 | 相机与显示 | 标准视图、显示风格、适配、视图设置 |
| 示例 | 可视化能力示范 | 高级、机械、基础示例 |
| 设置 | 应用级偏好 | 语言及后续持久化设置 |
| 帮助 | 使用说明 | 鼠标操作、关于 |

工具栏仅保留高频操作。具体建模命令不再随意堆入工具栏。

## 实施阶段

1. **SDK Consumer 边界**：Windows/Linux 都直接解析已安装 SDK Root，不 clone、不 sync、不重新构建 Bridge。
2. **功能目录**：建立共享菜单定义和强类型动作枚举，三端显式映射到实际方法。
3. **UI 统一**：统一菜单、工具栏、窗口骨架、颜色、间距、默认值和视图设置。
4. **能力验证**：按能力域保留必要的可视化综合案例和明确诊断，不建设第二套 Bridge 测试框架。
5. **新 API 覆盖**：持续跟进 main 新能力并通过已安装 SDK 编译验证。
6. **清理**：删除旧菜单构建器、重复 helper、失效同步脚本、外部 SDK 缓存和过时文档。
7. **发布门禁**：使用已安装 SDK 执行三端 Release 构建和核心交互回归。

## 完成标准

- Windows/Linux Demo 都只消费已安装 SDK。
- Demo 仓库中不存在 Bridge sync 脚本、Bridge 源码缓存或 Binary SDK 副本。
- 三端菜单、工具栏和 View Settings 的功能、默认值和命名一致。
- 禁止反射门禁、消费者边界检查和 Release 构建通过。
- 新建、打开、保存、撤销/重做、选择、视图、导入导出完成手工回归。
- 文档与实际 SDK 使用方式一致。
