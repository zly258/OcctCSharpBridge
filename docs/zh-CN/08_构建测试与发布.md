# 08 构建、测试与发布

## 构建目标

```powershell
.\build.ps1 validate Release
.\build.ps1 managed Release
.\build.ps1 test Release
.\build.ps1 all Release -OcctRoot "D:\tools\occt-vc144-64"
.\build.ps1 smoke Release -OcctRoot "D:\tools\occt-vc144-64"
.\build.ps1 docs Release
.\build.ps1 dist Release -OcctRoot "D:\tools\occt-vc144-64"
```

契约检查只负责验证真正的源码/ABI/构建不变量，不应替代实际编译和运行。Managed Regression、Native Smoke、Docs 与 Dist 都保留清晰的显式目标。

正式 Binary SDK 状态始终读取 `main/dist/win-x64/bridge-contract.json` 与 `bridge-manifest.json`，不要手工修改 Release 元数据，也不要在文档中重复硬编码一份“当前已发布版本”。

## Binary SDK 发布

只有 `main/dist/win-x64` 是 Git 跟踪的正式 Binary SDK。`publish.ps1` 必须从干净的命名 `main` 分支运行，并先验证本地 `main` 基于最新 `origin/main`。

```powershell
.\publish.ps1 -OcctRoot "D:\tools\occt-vc144-64"
```

正常流程：

```text
fetch 并验证 origin/main ancestry
→ 生成中英文 API 文档（非 -Fast）
→ 构建 Release dist
→ 校验 Contract / Manifest / SHA-256
→ dist/win-x64 有变化时提交
→ push main
```

## Demo 消费

`demo/dist` 已被 Git Ignore，不再由发布流程提交。切换到 demo 后：

```powershell
.\sync.ps1
.\build.ps1 all Release
```

`sync.ps1` 从当前 `origin/main/dist/win-x64` 复制**实际已发布**的 Binary SDK 到本地被忽略目录，并输出真实契约。

## 生成式 API 文档

`build.ps1 docs` 负责维护 `docs/zh-CN/api` 与 `docs/en-US/api`。当前源码 API 数量始终以 Source Contract 为准；正常 Release 时应重新生成 API Reference。
