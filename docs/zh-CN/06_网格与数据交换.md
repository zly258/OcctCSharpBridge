# 网格与数据交换

Core 提供可配置 Triangulation，以及基于 OCCT 7.9 契约 Toolkit 的 STEP、IGES、BREP、STL 等工程数据交换能力。

STEP 装配导入内部使用 XDE 保留 Product Hierarchy、Occurrence、Transform、Visibility、Color 与 Subshape Style；Managed 层输出 `OcctAssemblyDocument` / `OcctAssemblyNode` Snapshot，而不是暴露 OCAF Document。

源 STEP 中合法的 multi-solid Part 保持为一个逻辑 Part，不按 Solid 数量错误拆分。

几何未发生变化时，名称、颜色、透明度、显隐等非几何信息可以继续通过保留的 XDE 表达进行 round-trip。

这些 Core Exchange 语义与 UI Host 无关。WinForms、WPF、Avalonia 均消费同一套 `OcctNet` Core Contract；Linux Avalonia 与 Windows 使用相同 Exchange 模型，不存在独立分支专用契约。

## 后台导入到 Viewer

`OcctEngine.ImportAsync`、`ImportStepAsync`、`ImportIgesAsync`、`ImportBrepAsync` 和 `ImportStlAsync` 使用独立的 Headless `OcctModelingSession` 在线程池完成文件解析。解析完成后，只把 TopoDS Shape 复制到 Surface 线程并创建 AIS Viewer Shape，避免在后台线程访问 Viewer。

应用也可以调用 `CreateShapeFromModel(session, shape)`，把已有 Modeling Shape 安全加入 Viewer。该调用必须在 Engine 的 Surface 线程执行；Native 层会在 Modeling Session 锁内取得 Shape 副本，再创建 Viewer Presentation。

CancellationToken 在开始解析前和提交 Viewer 前生效。OCCT 文件解析开始后不会被强制中断，但取消后不会再把结果加入 Viewer。


## 网格直接缓冲区复制

`OcctMeshResource.CopyVertices(Span<OcctMeshVertex>)` 和 `CopyTriangles(Span<OcctModelMeshTriangle>)` 可把 Native 网格直接写入调用方提供并固定的缓冲区，避免面向对象网格快照产生的中间封送数组。该方式适合渲染上传、大模型处理以及复用 ArrayPool 缓冲区。

分配或租用缓冲区前先读取 `NodeCount` 和 `TriangleCount`。如果目标 Span 小于对应 Native 元素数量，复制开始前会直接拒绝调用。现有 `GetMesh()` 保持兼容。


逐面处理可使用 `GetFaceMeshCounts` 和 `CopyFaceMesh`。组合 Shape 网格现在会预先统计全部 Face 范围，只精确分配一次最终缓冲区，并把每个 Face 直接复制到最终切片，不再构造逐面临时网格或反复扩容 List。


## 编辑导入的 STEP/XDE 节点

`ImportStepDocument` 返回的节点可以通过 `SetStepNodeName`、`SetStepNodeVisibility` 和 `SetStepOccurrenceTransform` 编辑。定位使用 XDE Path ID 而不是显示名称，因此重名节点不会产生歧义。Occurrence Transform 仅允许修改组件实例节点。

Native 修改成功后会同步更新对应托管节点快照，使用 `ExportAllStep` 可写出保留的 XDE 文档。重新读取文档前，后代节点的 Global Transform 应视为导入时快照。


`AddStepComponent` 可以在 Assembly 下为已有 XDE Definition 创建新的 Occurrence，并返回刷新后的文档快照。`RemoveStepComponent` 会删除叶级 Occurrence 及其对应 Viewer 对象。两个操作返回前都会重建 Leaf-to-Viewer 映射。后续编辑应使用返回的新快照；旧快照继续表示其读取时刻的结构。
