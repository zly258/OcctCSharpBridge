# Demo 分支重整计划

## 目标与边界

- 以 `main@97e8d250fe90031899b94e9a1170b261a5aaa3a3` 生成的 ABI 5 Binary SDK 为当前基线。
- WPF、WinForms、Avalonia 使用同一套功能分类、菜单顺序、命名和默认设置。
- UI 只负责平台适配；命令定义、功能语义、测试场景和状态规则放在 `OcctDemo.Common`。
- 所有 Bridge 接口必须使用编译期可检查的强类型调用。禁止反射、`dynamic`、字符串方法名分发和 `DynamicInvoke`。
- Demo 保持 Binary SDK 消费者边界，不复制或引用 `main` 的 Bridge 源码工程。

## 信息架构

| 一级菜单 | 职责 | 主要内容 |
|---|---|---|
| 文件 | 文档生命周期和交换 | 新建、打开、保存、导入、导出、退出 |
| 编辑 | 已有对象操作 | 撤销、重做、变换、删除、选择、可见性 |
| 创建 | 新建几何与标注 | 曲线、基本体、特征、布尔、标注 |
| 检查 | 模型查询 | 包围盒、质量属性、拓扑、距离、有效性 |
| 视图 | 相机与显示 | 标准视图、显示风格、适配、视图设置 |
| 示例 | 可视化能力示范 | 高级、机械、基础示例 |
| 验证 | 可重复功能验证 | 建模、网格、交换和后续新增 API 场景 |
| 设置 | 应用级偏好 | 语言及后续持久化设置 |
| 帮助 | 使用说明 | 鼠标操作、关于 |

工具栏仅保留高频操作：文档、新建/打开/保存、撤销/重做、显示风格、适配、等轴测和选择模式。具体建模命令不再随意挑选到工具栏。

## 实施阶段

1. **基线固定**：确认 `main` 提交、ABI、目标框架和 SDK 同步边界。
2. **功能目录**：建立共享菜单定义和强类型动作枚举，三端显式映射到实际方法。
3. **UI 统一**：统一菜单、工具栏、窗口骨架、颜色、间距、默认值和视图设置。
4. **验证体系**：按能力域建立可重复场景，输出通过条件、结果对象和诊断文本。
5. **新 API 覆盖**：补齐 STEP/XDE 编辑、高级布尔、连续性/曲面质量、直接网格复制、Viewer 新选项等 main 新能力。
6. **清理**：删除旧菜单构建器、重复 helper、无入口功能、失效文本和过时文档。
7. **发布门禁**：Windows x64 上执行 SDK 同步、三端 Release 构建、验证菜单全跑和核心交互回归。

## 验证矩阵

| 能力域 | 自动/静态门禁 | Demo 交互验证 |
|---|---|---|
| 消费者边界 | Binary SDK 清单、ABI 和项目引用检查 | 三端启动并加载原生库 |
| 调用方式 | 禁止反射/动态分发扫描 | 菜单动作全部为显式强类型调用 |
| 几何与拓扑 | 编译覆盖、结果有效性断言 | 创建、特征、布尔、分析菜单 |
| 网格 | 数量、索引、来源区间、Span 复制断言 | 网格线框结果和诊断文本 |
| 数据交换 | 往返及文件存在性/内容检查 | 导入、导出、OBJ/glTF 验证 |
| Viewer | 三端构建和默认值一致性 | 相机、显示风格、ViewCube、选择 |
| STEP/XDE | 文档树与编辑结果断言 | 名称、样式、图层、可见性、装配变换 |

## 完成标准

- 三端菜单由同一个目录生成，命令与动作没有缺项。
- 三端工具栏和 View Settings 的功能、默认值和命名一致。
- 当前 SDK 暴露的能力均有明确归属：交互入口、验证场景，或标记为不适合 UI 展示的底层能力。
- 禁止反射门禁、消费者边界检查、三端 Release 构建全部通过。
- 验证菜单全部通过；新建、打开、保存、撤销/重做、选择、视图、导入导出完成手工回归。
- 旧菜单实现和无效重复代码已删除，文档与实际界面一致。
