# 架构与边界

`main` 保持 Bridge 与产品级 CAD/BIM 架构解耦：

```text
Application
   │
   ├─ OcctNet.WinForms ─┐
   ├─ OcctNet.Wpf ──────┤
   └─ OcctNet.Avalonia ─┤
                         ▼
                      OcctNet
                         │
                    stable C ABI
                         │
                     OcctNative
                         │
                      OCCT 7.9
```

`OcctNet` 提供强类型 Managed Semantics，`OcctNative` 负责 C++/OCCT 边界；WinForms/WPF 都只依赖 Core，互不引用。

Document、Feature Tree、Command/Tool、Undo/Redo、捕捉、夹点和项目持久化属于上层应用职责。

XDE 可以在 STEP 装配交换内部使用，但不会暴露成应用层 OCAF Document。

正式的 Avalonia Host 和 Windows/Linux 共用 Native Core 均由 `main` 维护。`demo` 与 `avalonia` 分支只消费发布的 SDK 产物，不保存私有 Bridge 实现。

操作系统集成被限制在 `src/OcctNative/platform`。窗口系统类型和调用（Win32 或 X11）不得进入公开 ABI 或其他 Native 领域。契约检查会递归扫描 Native 源码并强制执行该边界，后续源码也将按领域逐步迁入对应目录。

文件交换实现、STEP/XCAF Document 状态与导入来源元数据归属 `src/OcctNative/exchange`；三角网格提取归属 `src/OcctNative/mesh`。两个领域都不拥有 Viewer 状态，headless Modeling 通过共享 Modeling Session 使用它们。

选择状态、检测、选择覆盖层与操纵器归属 `src/OcctNative/selection`；视觉外观、覆盖层与自定义 Presentation 归属 `src/OcctNative/presentation`。二者使用 Viewer 服务，但不拥有 Viewer Context。

Engine 协调与结构化 Native ErrorContext 归属 `src/OcctNative/core`。Core 组合 ViewerContext、SceneRegistry、DocumentStore 与渲染状态，但不拥有 UI Framework Adapter，也不承载应用层 Document 或 Command 模型。

共享几何查询、点集合、解析与微分几何、平面构造、变换和 B-Spline 实现归属 `src/OcctNative/geometry`。面向 Viewer 的入口可使用 Engine 协调，而 headless 入口只使用 ModelingSession 状态。

Shape 遍历、拓扑查询、拓扑历史、Face 分析与持久拓扑引用归属 `src/OcctNative/topology`。它们操作 ModelingSession 拥有的 Shape，并与 Viewer/AIS 状态保持独立。

ModelingSession 生命周期、算法执行、Boolean/Feature/Healing、分析、惯性与相交实现归属 `src/OcctNative/modeling`。递归契约检查禁止 headless Modeling 源码依赖 Viewer/Core/AIS。冻结的 Engine/Modeling 显示桥接由 Scene compatibility adapter 实现，不属于 Modeling Core。
