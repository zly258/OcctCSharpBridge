# 构建、测试与发布

Bridge 3 在同一 ABI5-only 源码分支中维护 Windows 与 Linux x64 构建链。Windows 使用 PowerShell，Linux 使用 `build.sh`。

Windows x64：

```powershell
.\build.ps1 validate Release
.\build.ps1 native Release -OcctRoot "D:\tools\occt-vc144-64"
.\build.ps1 managed Release
.\build.ps1 test Release
.\build.ps1 smoke Release -OcctRoot "D:\tools\occt-vc144-64"
.\build.ps1 docs Release
.\build.ps1 dist Release -OcctRoot "D:\tools\occt-vc144-64"
```

Linux x64：

```bash
./build.sh validate Release
./build.sh managed Release
./build.sh native Release
./build.sh test Release
./build.sh smoke Release
./build.sh dist Release
```

静态校验包括版本/ABI、架构边界、Bulk ABI、Native Source Inventory，以及 Native/托管 API Surface 的精确匹配。

Windows `managed` 构建：

```text
OcctNet
OcctNet.WinForms
OcctNet.Wpf
OcctNet.Avalonia
```

Linux 托管构建只包含跨平台的 `OcctNet` 与 `OcctNet.Avalonia`；WinForms、WPF 保持 Windows-only。

Windows `dist` 输出 `dist/win-x64`，包含 `OcctNative.dll`、核心托管程序集以及三个 Windows 可消费 UI 适配器，其中包括 `OcctNet.Avalonia.dll`。Linux `dist` 输出 `dist/linux-x64`，包含 `libOcctNative.so`、`OcctNet.dll` 与 `OcctNet.Avalonia.dll`。

从正式 `main` 分支执行 Windows 发布：

```powershell
.\publish.ps1 -OcctRoot "D:\tools\occt-vc144-64"
```

发布流程会验证 ABI5-only 包契约并校验所有必需 SDK 文件的哈希。当前流程不使用 NuGet 发布，也不使用 GitHub Actions。
