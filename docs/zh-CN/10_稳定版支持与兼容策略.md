# 3.x Stable 支持与兼容策略

本文定义 OcctCSharpBridge 3.x 稳定版对第三方 Consumer 的长期边界。版本、ABI、OCCT、.NET 和平台事实以根目录 `bridge-contract.json` 为机器可读事实源。

## 1. 平台支持

### Windows x64

Windows x64 是 3.x **官方预编译发布平台**。正式 Release 提供 Windows Portable SDK，并通过 Native/Managed 编译、默认 .NET 10 回归与 Smoke、.NET 8/9/10 Runtime Matrix、UI Host Smoke 和隔离 Portable SDK Smoke 验证。

### Linux x64

Linux x64 是**源码支持平台**。Native Core、`OcctNet`、`OcctNet.Avalonia`、构建脚本、Headless Smoke 和 DISPLAY 相关 Avalonia Smoke 持续维护。

3.x 官方 Release 不承诺 Linux 预编译 Binary/Portable Asset。Linux 使用者应针对目标部署环境的 OCCT 7.9.0 与系统 ABI/Runtime 自行构建。

## 2. .NET 支持

发布 Managed Assembly 的兼容基线：

```text
Core/Avalonia: net8.0
WinForms/WPF:   net8.0-windows
```

仓库默认运行版本：

```text
ManagedTests/Core/Avalonia Smoke: net10.0
WinForms/WPF Smoke:                net10.0-windows
```

正式 Consumer 支持：

```text
.NET 8
.NET 9
.NET 10
```

net8 TFM 是 Binary SDK 的最低兼容基线，不代表默认开发/运行版本。日常验证默认运行在 .NET 10；Stable 发布还要求真实安装 Microsoft.NETCore.App 8.x、9.x、10.x，并分别执行 Native-backed Runtime Smoke。

## 3. Native ABI

Bridge 3.x 只支持 ABI 5：

```text
current = 5
minimumSupported = 5
```

稳定版规则：

- 已发布 ABI 5 导出不得删除；
- 参数、Calling Convention、返回类型和既有语义不得做破坏性修改；
- 已发布 ABI Struct 的字段布局保持兼容；
- 可扩展 Struct 继续遵守 `structSize` / `apiVersion` 契约；
- 新能力优先新增入口；
- ABI Breaking Change 必须进入新的 Major/ABI 方案。

Managed 与 Native 必须来自同一个 Bridge Build。

## 4. Managed API 兼容策略

3.x 内：

- Patch 版本以 Bug Fix、稳定性、性能、诊断和非破坏性增强为主；
- 不破坏性删除已发布 Public Type/Member；
- 允许 Additive API；
- 需要破坏公开语义的变更应评估新 Major 版本。

内部源码布局和私有实现不属于第三方兼容契约。

## 5. Threading

`OcctRuntime.Configure()` 应在第一次创建 Native-backed 对象前执行。

同一个 `OcctModelingSession` 及其资源默认不是并发线程安全对象，多线程访问必须由应用层串行化。

同一个 `OcctEngine` 与 Viewer/Scene 对象默认也不是并发线程安全对象。WinForms/WPF/Avalonia Host 必须遵守对应 UI Framework 的 UI Thread 规则，Bridge 不自动把后台线程调用 Marshal 到 UI Thread。

## 6. Ownership 与生命周期

- `OcctEngine` 拥有 Viewer/Scene Object ID，不同 Engine 的 ID 不得混用。
- `OcctModelingSession` 拥有普通 Modeling Shape/Operation ID 及相关资源，不同 Session 的 ID 不得混用。
- Managed `IDisposable` / Owned Resource 必须按 API 契约释放。
- Host 重建后临时 Native Binding 可能失效，应根据 Host 生命周期/generation 状态重建，不要长期缓存过期 Native Handle。

## 7. 单位、坐标与容差

普通 Modeling/Viewer 数值按应用统一单位解释，Bridge 不在普通建模调用中隐式进行项目单位转换。

STEP/IGES 的单位行为取决于 Translator 与文件元数据；严格项目单位一致性应在数据交换边界显式校验。

Bridge 使用 OCCT 三维笛卡尔几何语义，工程坐标系、项目原点与业务坐标转换由应用负责。

除公开 API 明确暴露 tolerance 参数外，容差遵循 OCCT Precision/Topology 语义。

## 8. Binary SDK 与 Portable SDK 升级

以下内容必须作为同一 Build 整体升级：

```text
OcctNet*.dll
runtime/
occt/resources/
bridge-contract.json
bridge-manifest.json
package-manifest.json
```

禁止混用不同版本或不同 `sourceCommit`。

## 9. Stable 发布 Gate

Windows Stable 正式发布统一使用：

```powershell
.\publish.ps1 `
  -OcctRoot "D:\tools\occt-vc144-64" `
  -Zip
```

Stable Contract 下，该入口会执行默认 .NET 10 Regression/Smoke、Stable API/ABI Baseline 检查、实际 .NET 8/9/10 Native Runtime Matrix、Portable SDK 打包以及清除开发机 OCCT 路径后的隔离运行。

`tools/validate-stable-release.ps1` 只作为旧命令兼容转发壳保留，不再维护第二套发布逻辑。

## 10. Linux 验证边界

Linux 不发布官方预编译包，但源码线应继续通过：

```bash
./build.sh validate Release
./build.sh all Release
```

有图形环境时：

```bash
./build.sh avalonia-smoke Release
```

Linux Regression/Smoke 默认运行在 .NET 10。发行版 ABI、打包和部署策略由源码使用者针对自己的目标环境负责。
