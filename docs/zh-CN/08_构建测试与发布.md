# 构建、测试与发布

Bridge 3.0 使用同一套 ABI5-only 源码维护 Windows x64 与 Linux x64，但 **3.x 官方预编译 Release 只发布 Windows x64**。Linux 保留源码构建、测试和 Avalonia 运行支持。

`bridge-contract.json` 是版本、ABI、OCCT、.NET、平台与分发策略的机器可读事实源。

## 1. .NET 策略

Bridge 3.0 明确区分**发布兼容基线**和**默认运行版本**：

```text
Binary SDK 兼容基线
  Core/Avalonia: net8.0
  WinForms/WPF:   net8.0-windows

默认开发/回归/Smoke 运行版本
  Core/Avalonia: net10.0
  WinForms/WPF:   net10.0-windows

Consumer 支持
  .NET 8 / .NET 9 / .NET 10
```

发布的 Managed DLL 保持 net8 TFM，确保同一份扁平 Binary SDK 可以被 .NET 8、9、10 Consumer 使用；日常项目验证默认运行在 .NET 10。Stable 发布时再分别在真实 .NET 8、9、10 Runtime 上执行 Native Smoke。

构建 SDK 使用稳定版 .NET 10 SDK，基线 `10.0.100`，`latestFeature`。

## 2. Consumer 快路径：`dist`

Windows：

```powershell
.\build.ps1 dist Release -OcctRoot "D:\tools\occt-vc144-64"
```

Linux：

```bash
./build.sh dist Release
```

`dist` 执行 Contract Check、Native + Managed 编译，并生成 Binary SDK、Manifest、Source Commit 和 Hash。它明确不执行 Consumer Matrix、Regression Tests 与 Smoke。

## 3. Windows 日常完整验证

```powershell
.\build.ps1 all Release -OcctRoot "D:\tools\occt-vc144-64"
```

完整验证包括：

```text
Repository / Contract 静态检查
Native Release (/W4 /WX)
Managed Release (warnings as errors)
.NET 8/9/10 Consumer 编译矩阵
ManagedTests：默认 .NET 10
Core Native Smoke：默认 .NET 10
WinForms Smoke：默认 .NET 10
WPF Smoke：默认 .NET 10
Avalonia Windows Smoke：默认 .NET 10
```

`build.ps1 sdk Release` 在完整验证后生成扁平 Binary SDK。

## 4. Windows Stable 正式发布

正式发布唯一入口：

```powershell
.\publish.ps1 `
  -OcctRoot "D:\tools\occt-vc144-64" `
  -Zip
```

Stable Contract 下，`publish.ps1` 自动完成：

1. Stable Contract 校验；
2. 冻结的 Managed API / Native ABI 兼容校验；
3. 完整 `build.ps1 sdk Release` Gate；
4. Binary SDK Source Identity / Hash 校验；
5. Windows Portable SDK + ZIP；
6. 真实 .NET 8、9、10 Native Runtime Smoke；
7. 解压 Portable ZIP 后，在清除开发机 OCCT 路径和环境变量的条件下执行隔离 Smoke。

验证机器必须实际安装 Microsoft.NETCore.App 8.x、9.x、10.x x64 Runtime。Runtime Matrix 只允许 Patch 级 Roll-forward，并由测试程序再次检查 `Environment.Version.Major`。

`tools/validate-stable-release.ps1` 仅作为旧命令的兼容转发壳保留，不再维护第二套发布逻辑。

## 5. Windows Target 职责

| Target | 职责 |
| --- | --- |
| `validate` | Repository/Contract 静态检查 |
| `native` | 构建 `OcctNative.dll` |
| `managed` | 构建正式 Core + UI Adapter Managed DLL |
| `consumer` | .NET 8/9/10 Consumer 编译矩阵 |
| `test` | Managed Regression Tests，默认 .NET 10 |
| `smoke` | Core Native Smoke，默认 .NET 10 |
| `viewport-smoke` | WinForms/WPF/Avalonia Smoke，默认 .NET 10 |
| `dist` | Consumer Binary SDK 快路径，不跑 Regression/Smoke |
| `sdk` | 完整 Windows SDK Gate + Binary SDK |
| `all` | 完整本地验证，不生成正式 Portable 包 |
| `clean` | 删除生成输出 |

## 6. Linux 源码验证

Linux 不发布官方预编译 Release，但源码线保持可编译、可运行：

```bash
./build.sh validate Release
./build.sh all Release
```

有图形环境时：

```bash
./build.sh avalonia-smoke Release
```

Linux 的 Regression/Smoke 项目同样默认 `net10.0`；使用者自行生成的 Binary SDK Managed DLL 仍保持 `net8.0` 兼容基线。

`publish.sh` / `tools/package-portable-sdk.sh` 可以用于开发、内部验证或使用者自行打包，但其 Linux 输出不是官方 Release Asset，也不承诺跨发行版 glibc/libstdc++ 兼容。

## 7. SDK 布局

Windows Binary SDK：

```text
dist/win-x64/
  OcctNative.dll
  OcctNet.dll
  OcctNet.WinForms.dll
  OcctNet.Wpf.dll
  OcctNet.Avalonia.dll
  bridge-contract.json
  bridge-manifest.json
```

Windows Portable SDK：

```text
OcctCSharpBridge-<version>-win-x64-portable/
  OcctNet*.dll
  bridge-contract.json
  bridge-manifest.json
  package-manifest.json
  runtime/
  occt/resources/
  licenses / notices
```

`dist/`、`build/`、`artifacts/` 都属于生成目录，不提交到源码仓库。

## 8. 正式发布顺序

```text
main-dev Stable candidate
        ↓
publish.ps1 -Zip
        ↓
0 warning / 0 test failure / 0 smoke failure
        ↓
将同一个已验证 Commit 提升到 main
        ↓
main 再运行 publish.ps1 -Zip
        ↓
Tag v3.x.y
        ↓
发布 Windows x64 Portable ZIP + checksum / release notes
```

Linux 不上传官方预编译 Asset。
