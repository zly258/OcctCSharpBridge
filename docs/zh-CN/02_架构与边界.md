# 架构与边界

`main` 保持 Bridge 与产品级 CAD/BIM 架构解耦：

```text
Application
   │
   ├─ OcctNet.WinForms ─┐
   ├─ OcctNet.Wpf ──────┤
   └─ OcctNet.Avalonia ─┤
                         ▼
                      OcctNet
                         │
                     ABI5 C API
                         │
                     OcctNative
                         │
                      OCCT 7.9
```

`OcctNet` 提供强类型 Managed Semantics，`OcctNative` 负责 C++/OCCT 边界；各 UI Adapter 都依赖 Core，互不引用。

Document、Feature Tree、Command/Tool、Undo/Redo、捕捉、夹点和项目持久化属于上层应用职责。

XDE 可以在 STEP 装配交换内部使用，但不会暴露成应用层 OCAF Document。

正式 WinForms/WPF/Avalonia Adapter 与 Windows/Linux 共用 Native Core 均由 `main` 维护。统一 `demo` 分支只消费生成的 Binary SDK：Windows x64 提供 WinForms、WPF、Avalonia，Linux x64 仅提供 Avalonia；Demo 不保存私有 Bridge 实现。

## 领域目录

Managed 与 Native 使用同一套**领域级职责边界**，而不是继续采用扁平源码目录，也不是机械地逐文件一一镜像。Managed 的公开 Namespace 仍保持 `OcctNet`；目录只表达源码内部所有权，不制造无意义的公开 Namespace。

```text
src/OcctNet/                 src/OcctNative/
├─ Core/                     ├─ core/
├─ Exchange/                 ├─ exchange/
├─ Geometry/                 ├─ geometry/
├─ Mesh/                     ├─ mesh/
├─ Modeling/                 ├─ modeling/
├─ Platform/                 ├─ platform/
├─ Presentation/             ├─ presentation/
├─ Scene/                    ├─ scene/
├─ Selection/                ├─ selection/
└─ Topology/                 └─ topology/
                              └─ viewer/
```

Managed P/Invoke 声明必须放在所属领域的 `Interop/` 目录中。ABI5 架构不保留根目录 `NativeMethods.*` 大杂烩，不保留 `*.Current.*` 迁移命名，也不保留 Compatibility/Legacy 类源码名称。

Managed 根目录只保留 `AssemblyInfo.cs`、`GlobalUsings.cs`、`OcctNet.csproj` 等项目级文件。Native 根目录只保留 `CMakeLists.txt`、`OcctNative.h`、`OcctStatus.h` 等构建/ABI 总入口文件；具体领域实现必须归入对应目录。

## Native 边界

操作系统集成被限制在 `src/OcctNative/platform`。窗口系统类型和调用不得进入公开 ABI 或其他 Native 领域。

文件交换实现、STEP/XCAF Document 状态与导入来源元数据归属 `src/OcctNative/exchange`；三角网格提取归属 `src/OcctNative/mesh`。两个领域都不拥有 Viewer 状态，Headless Modeling 通过共享 Modeling Session 使用它们。

选择状态、检测、选择覆盖层与操纵器归属 `src/OcctNative/selection`；视觉外观、Overlay、Annotation 与自定义 Presentation 归属 `src/OcctNative/presentation`。二者使用 Viewer 服务，但不拥有 Viewer Context。

Engine 协调与结构化 Native Error State 归属 `src/OcctNative/core`。Core 组合 ViewerContext、SceneRegistry、DocumentStore 与渲染状态，但不拥有 UI Framework Adapter，也不承载应用层 Document 或 Command 模型。

共享几何查询、点集合、解析与微分几何、平面构造、变换和 B-Spline 实现归属 `src/OcctNative/geometry`。面向 Viewer 的入口可以使用 Engine 协调，而 Headless 入口只使用 ModelingSession 状态。

Shape 遍历、拓扑查询、拓扑历史、Face 分析与持久拓扑引用归属 `src/OcctNative/topology`。它们操作 ModelingSession 拥有的 Shape，并与 Viewer/AIS 状态保持独立。

ModelingSession 生命周期、算法执行、Boolean/Feature/Healing、分析、惯性与相交实现归属 `src/OcctNative/modeling`。递归契约检查禁止 Headless Modeling 源码依赖 Viewer/Core/AIS。Engine/Modeling 的 Presentation 集成通过 Scene Interop 边界实现，不属于 Modeling Core。
