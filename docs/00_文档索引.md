# 00 文档索引

本目录是 `OcctCSharpBridge` 的核心技术文档。根目录继续保留 `README.md` 与 `README.zh-CN.md` 两个项目入口；`docs` 只维护一套中文技术正文，API、类型名、文件名和命令保持英文原名，避免中英文双份文档长期漂移。

| 项目 | 当前值 |
|---|---|
| Bridge | `2.6.0` |

## 仓库职责

```text
OcctCSharpBridge
├─ bridge-contract.json          版本、平台和 API 数量的机器可读契约
├─ src/OcctNative               C++17 + OCCT + 稳定 C ABI
├─ src/OcctNet                  核心 .NET Bridge
├─ src/OcctNet.WinForms         WinForms HWND Host
├─ src/OcctNet.Wpf              WPF Host
├─ src/OcctNet.Avalonia         Avalonia Windows HWND Host
├─ tests                         静态契约、Managed 回归、Native Smoke
├─ docs                          本目录：设计与使用说明
└─ build.ps1                    validate/build/pack/smoke 统一入口
```

`main` 只提供可复用 OCCT Bridge，不实现完整 CAD 应用框架。Document、Feature Tree、Command、Tool、Undo/Redo、Snap、Grip、项目 JSON 持久化以及具体 BIM/设备业务规则属于 `demo` 或其它上层项目。

## 文档维护原则

1. **代码和 `bridge-contract.json` 是事实来源。** 文档不通过复制配置制造第二份真相。
2. **一个主题只保留一个主文档。** 不再维护 `.md` 与 `.zh-CN.md` 两套正文。
3. **只写已经存在的能力。** 不把计划、设想和未实现接口混入 API 使用说明。
4. **公共 API 用真实类型和方法名说明。** 示例应能对应当前 `main` 源码。
5. **不记录阶段性开发流水账。** 历史由 Git Commit/PR 承担，docs 关注长期有效的设计和使用规则。
6. **架构边界优先于“功能越多越好”。** Bridge 不重新吸收应用层 CAD Framework。

## 常用入口

只做静态和 Managed 校验：

```powershell
.\build.ps1 validate Release
.\build.ps1 managed Release
```

构建 Managed NuGet：

```powershell
.\build.ps1 pack Release
```

使用本机 OCCT 7.9.0 执行完整 Native 门禁：

```powershell
.\build.ps1 smoke Release
```

从头执行全部流程：

```powershell
.\build.ps1 all Release
```
