# 运行时部署与诊断

Bridge 3 是 **ABI5-only、跨平台 x64 SDK**。源码契约同时支持 `windows-x64` 与 `linux-x64`，具体 UI Adapter 仍按框架和平台边界拆分。

Native Bridge 与 OCCT Kernel 使用平台自身的正式文件名，不把其它名称作为兼容别名：

```text
Windows x64: OcctNative.dll     / TKernel.dll
Linux x64:   libOcctNative.so   / libTKernel.so
```

`OcctRuntime` 只解析当前平台布局。Native Bridge 候选包括应用目录、`runtimes/<rid>/native`、显式配置目录、`OCCT_BRIDGE_NATIVE_DIR`、Portable Runtime 目录，以及启用 Repository Probing 时的当前仓库构建输出。Windows RID 为 `win-x64`，Linux RID 为 `linux-x64`；不保留旧 Native Library Name fallback。

Windows 默认开发环境 OCCT 路径：

```text
D:\tools\occt-vc144-64\inc
D:\tools\occt-vc144-64\win64\vc14\lib
D:\tools\occt-vc144-64\win64\vc14\bin
```

Linux 默认使用 `/usr/local/include/opencascade` 与 `/usr/local/lib`，也可以通过构建环境覆盖。Linux Runtime Probing 使用配置的 OCCT Library 目录，不复用 Windows `win64/vc14` 路径。

`OcctRuntime` 要求受支持的 64 位进程，并通过诊断 API 输出当前平台、配置的 Native Bridge/OCCT 路径、Bridge 候选路径以及已经加载的运行时模块。

`OcctNet.dll` 与 Native Bridge 必须来自**同一次 Bridge 构建**。运行时校验要求 ABI 必须为 5，并且 Bridge 版本完全一致；不再把更高或更低的 Native Bridge 版本作为兼容替代。

`dist/win-x64` 与 `dist/linux-x64` 都是 Bridge Binary SDK，不等于完整应用 Runtime Closure。实际应用仍需根据目标平台、发布策略和第三方许可证部署 OCCT 及相关运行库。

WinForms、WPF Adapter 仅面向 Windows；核心 `OcctNet` 与 Avalonia Adapter 构成 Linux Consumer 使用的跨平台 Managed Surface。
