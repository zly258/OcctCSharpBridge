# 01 快速开始

本项目面向 **Windows x64 + .NET 10 + Open CASCADE Technology 7.9.0**。核心程序集 `OcctNet` 提供两个主要入口：

- `OcctModelingSession`：无窗口建模、拓扑、算法、分析、网格和数据交换；
- `OcctEngine`：AIS/Viewer、对象显示、选择、相机、外观、标注和交互。

WinForms、WPF、Avalonia 是不同 UI 框架中的可复用 Viewport Host。

## 1. 环境要求

```text
Windows x64
.NET SDK 10.0.302
Visual Studio 2022 / MSVC
CMake 3.21+
Open CASCADE Technology 7.9.0
```

默认 OCCT 根目录：

```text
D:\tools\occt-vc144-64
```

也可以通过 `-OcctRoot` 或 `OCCT_ROOT` 指定其它位置。

## 2. 先验证 Managed 层

不需要 OCCT SDK：

```powershell
.\build.ps1 validate Release
.\build.ps1 managed Release
.\build.ps1 test Release
```

- `validate`：运行仓库级静态契约；
- `managed`：增量构建 `OcctNet` 与三个 UI Host；
- `test`：构建并通过 .NET 10 Microsoft Testing Platform 执行 Managed Regression。

## 3. 构建完整 Bridge

```powershell
.\build.ps1 all Release -OcctRoot "D:\tools\occt-vc144-64"
```

真实 Native 运行验证：

```powershell
.\build.ps1 smoke Release -OcctRoot "D:\tools\occt-vc144-64"
```

只有 Native Smoke 能证明 C++ 编译、链接、`OcctNative.dll`/OCCT 依赖加载以及真实几何/拓扑执行路径正常。

## 4. 生成正式 Binary SDK

其它项目不应 clone 并重新编译整个 Bridge，而应消费已验证的 Binary SDK：

```powershell
.\build.ps1 dist Release -OcctRoot "D:\tools\occt-vc144-64"
```

`dist` 要求 Git 工作区干净，并自动完成 Native Build、Managed Build、Managed Test、Native Smoke 后才刷新：

```text
dist/win-x64/
├─ OcctNative.dll
├─ OcctNet.dll
├─ OcctNet.WinForms.dll
├─ OcctNet.Wpf.dll
├─ OcctNet.Avalonia.dll
├─ bridge-contract.json
└─ bridge-manifest.json
```

`bridge-manifest.json` 记录源码 Commit 和每个文件的 SHA-256，确保 Native 与 Managed Wrapper 成套使用。

正式将 Binary SDK 发布到 demo：

```powershell
.\publish.ps1 -OcctRoot "D:\tools\occt-vc144-64"
```

## 5. 构建 Managed NuGet

```powershell
.\build.ps1 pack Release
```

输出位于 `artifacts\packages`。例如：

```powershell
dotnet add package OcctNet --version 2.6.0 --source .\artifacts\packages
dotnet add package OcctNet.Wpf --version 2.6.0 --source .\artifacts\packages
```

Managed NuGet 不捆绑 `OcctNative.dll` 和 OCCT `TK*.dll`。

## 6. 生成完整中英文 API 文档

```powershell
.\build.ps1 docs Release
```

生成器从四个公开程序集、XML Documentation 与 `src/OcctNative/OcctNative.h` 生成完整 Managed + Native API Reference：

```text
docs/zh-CN/api/reference/**
docs/zh-CN/api/native-abi.md
docs/en-US/api/reference/**
docs/en-US/api/native-abi.md
```

每个 Managed 类型页面包含程序集、命名空间、声明、构造函数、属性、事件、方法、参数、返回类型和字段/枚举值；`native-abi.md` 覆盖 Native ABI 类型与全部 `OCCTBRIDGE_API occt_*` 导出。入口见 [完整 API Reference](api/README.md)。

## 7. Headless 建模

```csharp
using OcctNet;

using var model = new OcctModelingSession();

var plate = model.MakeBox(100, 80, 10);
var hole = model.MakeCylinder(
    new OcctPoint3d(50, 40, -5),
    OcctVector3d.UnitZ,
    8,
    20);

var cut = model.Cut(plate, hole);
var bounds = model.GetShapeBounds(cut.Shape);
var inertia = model.GetVolumeInertiaProperties(cut.Shape);
var inspection = model.InspectShape(cut.Shape);
model.ExportStep(cut.Shape, "plate.step");
```

`OcctModelShape` 与创建它的 `OcctModelingSession` 绑定，不要保存裸 ID 后在另一个 Session 中复用。

## 8. Viewer

直接使用 `OcctEngine` 需要有效的原生窗口句柄：

```csharp
using var engine = new OcctEngine();
engine.Initialize(hwnd);
engine.SetView(OcctViewOrientation.Isometric);
engine.SetProjection(OcctProjectionType.Orthographic);
engine.FitAll();
```

桌面应用通常使用对应 Host：

```text
WinForms  -> OcctViewportControl
WPF       -> OcctWpfViewport
Avalonia  -> OcctAvaloniaViewport
```

`OcctNet.Avalonia` 当前通过 Windows HWND 承载 Viewer，因此仍是 Windows Host。

## 9. Headless Shape 显示到 Viewer

```csharp
using var model = new OcctModelingSession();
var shape = model.MakeBox(100, 80, 60);

using var engine = new OcctEngine();
engine.Initialize(hwnd);
var displayed = engine.Display(model, shape, fit: true);
```

`displayed` 属于目标 `OcctEngine`；原始 `OcctModelShape` 仍属于 Modeling Session。

## 10. Runtime 配置

Bridge 开发目录下可显式配置：

```csharp
OcctRuntime.Configure(
    occtRoot: @"D:\tools\occt-vc144-64",
    nativeBridgeDirectory: @"D:\workspace\OcctCSharpBridge\build\native\bin\Release");
```

Binary SDK 消费项目则通常将 `OcctNative.dll` 放到应用输出目录，并配置 `OCCT_ROOT`。出现 DLL 加载问题时输出：

```csharp
Console.WriteLine(OcctRuntime.GetDiagnosticReport());
```

## 11. 推荐本地门禁

日常 Managed 修改：

```powershell
.\build.ps1 validate Release
.\build.ps1 managed Release
.\build.ps1 test Release
```

涉及 Native/ABI：

```powershell
.\build.ps1 all Release
.\build.ps1 smoke Release
```

更新公开 API 文档：

```powershell
.\build.ps1 docs Release
```

准备/发布 Binary SDK：

```powershell
.\build.ps1 dist Release
.\publish.ps1
```

仓库不使用 GitHub Actions 代替这些真实本地门禁。
