CAPABILITIES

A focused foundation for CAD, BIM and engineering software

The Bridge stays close to OCCT geometry and interaction while leaving product documents and domain workflows to the consuming application.

01

Viewer & AIS

Camera, projection, display modes, materials, color, transparency, transforms, text, dimensions, lighting and redraw batching.

02

Headless modeling

Primitives, Boolean operations, extrude, revolve, sweep, loft, fillet, chamfer, offset, shelling, healing and operation history.

03

Selection & input

Point/rectangle selection, structured selected and detected identities, selectable state and raw input forwarding for custom CAD tools.

04

Geometry & topology

Evaluation, curvature, projection, distance, adjacency, inertia, intersections, shape inspection and persistent topology references.

05

Meshing

Configurable triangulation with combined node/triangle arrays and explicit per-face provenance ranges.

06

STEP assembly exchange

First-class XDE-derived assembly snapshots preserve hierarchy, occurrences, transforms, visibility, colors and subshape styles.

07

First-class points

Real AIS_Point objects and standard OCCT point markers for CAD capture points, grips and lightweight interactive geometry.

08

Desktop hosts

Independent WinForms, WPF HwndHost and Avalonia Windows-HWND adapters over the same core engine.

ARCHITECTURE

Clear boundaries instead of a monolithic CAD framework

OcctCSharpBridge provides geometry, presentation and interaction primitives. Product state remains owned by your application.

01

Application documents stay above the Bridge

Feature trees, commands, undo/redo, snapping rules and project persistence are application responsibilities.

02

XDE is internal to STEP exchange

XDE preserves real STEP product structure and styles, then projects them to OcctAssemblyDocument. It is not exposed as the application document model.

03

Stable managed semantics

Strong types, explicit ownership and bulk Native calls keep the managed API predictable and avoid high-cardinality N+1 interop patterns.

04

UI hosts stay independent

WinForms, WPF and Avalonia all depend on OcctNet directly. WPF uses native HwndHost rendering with coalesced resize presentation.

GET STARTED

Build the Bridge or run the Binary SDK demos

Main produces the validated SDK. Demo keeps its local dist ignored and synchronizes the current published payload when needed.

PowerShell
# Build / publish Bridge from main
.\build.ps1 all Release -OcctRoot "D:\tools\occt-vc144-64"
.\publish.ps1 -OcctRoot "D:\tools\occt-vc144-64"

# Consume the published SDK from demo
git switch demo
.\sync.ps1
.\build.ps1 all Release
.\run.ps1 wpf Release
