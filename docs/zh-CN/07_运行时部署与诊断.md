# 运行时部署与诊断

Bridge 3 是 **ABI5-only、跨平台 x64 SDK**。源码契约同时支持 `windows-x64` 与 `linux-x64`，具体 UI Adapter 仍按框架和平台边界拆分。

Native Bridge 与 OCCT Kernel 使用平台自身的正式文件名，不把其它名称作为兼容别名：

```text
Windows x64: OcctNative.dll     / TKernel.dll
Linux x64:   libOcctNative.so   / libTKernel.so
```

`OcctRuntime` 只解析当前平台布局。Native Bridge 候选包括应用目录、应用目录下的 `runtime/`、`runtimes/<rid>/native`、显式配置目录、`OCCT_BRIDGE_NATIVE_DIR`、旧 Portable Runtime 相对目录，以及启用 Repository Probing 时的当前仓库构建输出。Windows RID 为 `win-x64`，Linux RID 为 `linux-x64`；不保留旧 Native Library Name fallback。

Portable SDK 推荐直接保持以下布局并整体复制到应用输出目录：

```text
<app>/
  OcctNet.dll
  OcctNet.WinForms.dll        # Windows only
  OcctNet.Wpf.dll             # Windows only
  OcctNet.Avalonia.dll
  bridge-contract.json
  bridge-manifest.json
  package-manifest.json
  runtime/
    OcctNative.dll            # Windows
    libOcctNative.so          # Linux
    <OCCT/third-party native dependency closure>
  occt/
    resources/
      ...
```

在此布局下，应用只需在第一次创建 `OcctEngine` 或 `OcctModelingSession` 前调用：

```csharp
OcctRuntime.Configure();
```

`OcctRuntime` 会自动解析 `<app>/runtime` 与 `<app>/occt`，无需目标机再设置开发机的 `OCCT_ROOT` / `CASROOT`。Windows Portable SDK 还会收集实际依赖的 VC Runtime DLL；Linux Portable SDK 会收集 OCCT/TBB/FreeImage 等非系统运行库，并把包内 ELF RPATH 调整为 `$ORIGIN`。Linux 系统库（例如 glibc、OpenGL、X11/Wayland 组件）不属于 SDK 私有运行时闭包，仍由目标 Linux 系统提供。

Windows 默认开发环境 OCCT 路径：

```text
D:\tools\occt-vc144-64\inc
D:\tools\occt-vc144-64\win64\vc14\lib
D:\tools\occt-vc144-64\win64\vc14\bin
```

Linux 默认使用 `/usr/local/include/opencascade` 与 `/usr/local/lib`，也可以通过构建环境覆盖。Linux Runtime Probing 使用配置的 OCCT Library 目录，不复用 Windows `win64/vc14` 路径。

`OcctRuntime` 要求受支持的 64 位进程，并通过诊断 API 输出当前平台、配置的 Native Bridge/OCCT 路径、Bridge 候选路径以及已经加载的运行时模块。

`OcctNet.dll` 与 Native Bridge 必须来自**同一次 Bridge 构建**。运行时校验要求 ABI 必须为 5，并且 Bridge 版本完全一致；不再把更高或更低的 Native Bridge 版本作为兼容替代。

`dist/win-x64` 与 `dist/linux-x64` 仍是供机器校验、Demo 同步使用的**最小 Binary SDK**，故意不塞入 OCCT Runtime Closure。面向人工交付时使用 `publish.ps1` / `publish.sh`，它们在完整 Release Gate 之后生成 `artifacts/publish/OcctCSharpBridge-<version>-<rid>-portable` Portable SDK，并附带 License/Notices 与完整 `package-manifest.json` 哈希清单。

Portable SDK **不捆绑 .NET Runtime**；它解决的是 Bridge + OCCT Native Runtime 的可携带部署。应用可以自行选择 framework-dependent 或 self-contained .NET 发布方式。

WinForms、WPF Adapter 仅面向 Windows；核心 `OcctNet` 与 Avalonia Adapter 构成 Linux Consumer 使用的跨平台 Managed Surface。
