# 08 构建测试与发布

`build.ps1` 是 `main` 的统一本地入口。构建、测试和发布现在明确解耦：**静态契约检查与 Release 编译属于构建/发布链；Managed Regression 与 Native Smoke 是显式测试目标，不再阻塞 `dist` 或 `publish`。**

## 1. 当前基础契约

`bridge-contract.json` 是版本、平台和 API 数量的机器可读事实源。当前基线：Bridge `2.6.0`、Native ABI `4`、OCCT `7.9.0`、Native/PInvoke `344/344`、Viewer/Modeling `210/134`、.NET SDK `10.0.302`、`net10.0-windows`、C# `14.0`。

## 2. build target

```powershell
.\build.ps1 validate Release
```
执行长期仓库静态契约，不需要 OCCT SDK。

```powershell
.\build.ps1 managed Release
```
增量构建 `OcctNet` 与三个 UI Host。

```powershell
.\build.ps1 test Release
```
显式执行 Managed Regression。该目标不属于 `dist` / `publish`。

```powershell
.\build.ps1 native Release
```
使用 CMake + MSVC + OCCT 7.9.0 构建 `OcctNative.dll`。

```powershell
.\build.ps1 smoke Release
```
显式构建并执行真实 Native Smoke。该目标用于诊断 Native/OCCT 行为，但不属于 Binary SDK 发布门禁。

```powershell
.\build.ps1 pack Release
```
生成并校验四个 Managed NuGet/Symbol Package；Managed 包不包含 OCCT Runtime 或 `OcctNative.dll`。

```powershell
.\build.ps1 docs Release
```
构建 Managed SDK 后运行 `tools/OcctApiDocsGenerator`，生成完整中英文公开 API Reference。

```powershell
.\build.ps1 all Release
```
构建 Native + 四个 Managed SDK 项目，不隐式执行 test/smoke。

```powershell
.\build.ps1 clean Release
```
清理生成的 build/artifacts/bin/obj，不删除已提交的 `dist/`。

## 3. Binary SDK：`build.ps1 dist`

正式二进制只允许 Release：

```powershell
.\build.ps1 dist Release
```

要求 Git 工作区干净，并按顺序完成：

```text
仓库静态契约
→ Native Release build
→ Managed Release build
→ 收集 Binary SDK
→ SHA-256
→ bridge-manifest.json
→ staging
→ 原子替换 dist/win-x64
```

**`dist` 不运行 Managed Test，也不运行 Native Smoke。** 测试失败不会阻止生成 Binary SDK；需要测试时显式运行 `test` 或 `smoke`。

生成：

```text
dist/win-x64/
├─ OcctNative.dll
├─ OcctNet.dll
├─ OcctNet.WinForms.dll
├─ OcctNet.Wpf.dll
├─ OcctNet.Avalonia.dll
├─ bridge-contract.json
└─ bridge-manifest.json
```

Manifest 记录 Bridge Version、Native ABI、OCCT Version、Target Framework、SDK/Language Version、Release Configuration、源码 Commit 和所有分发文件 SHA-256。正式 `dist` 使用 staging/backup 原子替换，避免失败后留下半套 DLL。

## 4. 正式发布：`publish.ps1`

正常发布无需重复指定默认 OCCT 路径：

```powershell
.\publish.ps1
```

发布要求 `main` 工作区开始时完全干净。脚本执行：

```text
build.ps1 docs Release
→ 生成完整 zh-CN/en-US API Reference
→ API Reference 有变化则 commit
→ 再次确认工作区干净
→ build.ps1 dist Release
→ Native + Managed Release Build
→ 生成/校验 Binary SDK Contract / Manifest / SHA-256
→ commit dist/win-x64
→ push main
→ fetch demo
→ 临时 detached worktree
→ 只同步 demo/dist/win-x64
→ 再次校验 Contract / Manifest / SHA-256
→ commit + push demo
→ 删除临时 worktree
```

`publish.ps1` **不会调用 `test` 或 `smoke`**。`-Fast` 只跳过 API 文档生成，不再与测试行为耦合。

这个顺序保证 `bridge-manifest.json.sourceCommit` 精确对应生成 DLL 的源码和已提交公开 API 文档。脚本不会切换当前开发目录分支，也不使用 GitHub Actions。

## 5. 测试职责

测试保留，但完全独立：

```powershell
# Managed 回归
.\build.ps1 test Release

# Native / OCCT 真实场景
.\build.ps1 smoke Release
```

Native Smoke 主要验证 C++ 编译/链接、OCCT Runtime 加载、几何/拓扑算法、Viewer/Selection、Mesh/Exchange 以及 ABI Struct 的真实调用行为。它用于暴露实现问题，不再承担“能否发布 Binary SDK”的控制职责。

## 6. 推荐流程

普通开发需要快速编译：

```powershell
.\build.ps1 all Release
```

需要针对性回归时再执行：

```powershell
.\build.ps1 test Release
.\build.ps1 smoke Release
```

只准备 Binary SDK：

```powershell
.\build.ps1 dist Release
```

正式发布 API 文档 + main Binary SDK + demo：

```powershell
.\publish.ps1
```

本仓库不使用 GitHub Actions。
