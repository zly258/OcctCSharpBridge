# 03 API Coverage and Design Conventions

## Current contract

From `bridge-contract.json`:

- Bridge 2.7.0
- Native ABI 4
- 349 Native exports
- 349 managed P/Invoke mappings
- 117 public .NET types
- Viewer API count 215
- Modeling API count 134

The ABI version changes only for incompatible Native contract changes. Additive APIs can keep the same ABI while the Bridge semantic version advances.

## Public API groups

- viewer/camera/rendering and appearance;
- selection, hit testing, selectability and raw input;
- first-class shapes, text, dimensions and `AIS_Point`-backed points;
- headless primitives, booleans, features, healing and modeling history;
- geometry/topology evaluation, adjacency, curvature, inertia, intersections and persistent topology references;
- meshing and per-face provenance;
- STEP/IGES/BREP/STL exchange;
- first-class STEP assembly snapshot (`OcctAssemblyDocument`).

## Conventions

- prefer strong value types over magic arrays/strings;
- batch Native calls for high-cardinality queries instead of N+1 P/Invoke loops;
- keep object ownership explicit;
- do not reintroduce removed legacy aliases simply to preserve accidental API surface;
- use `bridge-contract.json` rather than hard-coded documentation counts.
