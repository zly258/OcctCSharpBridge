# 构建、测试与发布

Bridge 3 使用同一套 ABI5-only 源码维护 Windows x64 与 Linux x64。`bridge-contract.json` 是版本、ABI、OCCT、.NET 与平台要求的机器可读事实源。

## 1. 环境要求

Windows x64：

- Windows x64；
- Visual Studio 2022 / MSVC x64 C++ 工具链；
- CMake >= `bridge-contract.json` 中声明的最低版本；
- OCCT **7.9.0** x64；
- .NET SDK **10.0.303 精确版本**；
- C# 14；
- PowerShell。

Linux x64：

- Linux x64；
- C++17 编译器；
- CMake；
- OCCT 7.9.0；
- .NET SDK 10.0.303 精确版本。

根目录 `global.json` 禁止 SDK roll-forward。不要通过降低版本要求或启用 roll-forward 绕过契约。

Windows 默认 OCCT 路径为：

```text
D:\tools\occt-vc144-64
```

也可以设置：

```powershell
$env:OCCT_ROOT = "E:\SDK\occt-7.9.0"
```

或在命令中显式传入：

```powershell
.\build.ps1 native Release -OcctRoot "E:\SDK\occt-7.9.0"
```

## 2. Windows build.ps1

语法：

```powershell
.\build.ps1 [Target] [Configuration] [-OcctRoot <path>]
```

默认值：

```text
Target        = all
Configuration = Release
```

支持配置：`Debug`、`Release`、`RelWithDebInfo`。`dist` 只允许 `Release`。

### Target 说明

| Target | 做什么 | 需要 OCCT | 需要 .NET SDK |
| --- | --- | --- | --- |
| `validate` | 只执行仓库级静态 Contract Checks | 否 | 不执行 dotnet 构建 |
| `native` | 静态检查 + 配置/编译 `OcctNative.dll` | 是 | 否 |
| `managed` | 静态检查 + 构建 Core、WinForms、WPF、Avalonia | 否 | 是 |
| `test` | 静态检查 + 构建并运行 Managed regression tests | 否 | 是 |
| `smoke` | 静态检查 + Native + Managed + 真实 Native Smoke | 是 | 是 |
| `dist` | 静态检查 + Release Native/Managed + 生成 `dist/win-x64` | 是 | 是 |
| `clean` | 删除 CMake/MSBuild 生成目录，不执行契约检查 | 否 | 否 |
| `all` | 完整本地验证：静态检查 + Native + Managed + Managed Tests + Native Smoke | 是 | 是 |

常用命令：

```powershell
# 仅检查源码契约与架构边界
.\build.ps1 validate Release

# 只编译 Native
.\build.ps1 native Release

# 只编译 Managed SDK
.\build.ps1 managed Release

# Managed 回归测试
.\build.ps1 test Release

# 完整 Native Smoke
.\build.ps1 smoke Release

# 推荐的完整验证
.\build.ps1 all Release

# 生成 Windows Binary SDK；要求干净工作区且只能 Release
.\build.ps1 dist Release

# 清理生成输出
.\build.ps1 clean
```

`build.ps1` 对除 `clean` 外的 target 都先执行静态 Contract Checks。`all` 不生成 Binary SDK，也不会修改 `dist`。

### all 的执行顺序

```text
Static Contract Checks
        ↓
Native CMake configure/build
        ↓
OcctNet + WinForms + WPF + Avalonia
        ↓
OcctNet.ManagedTests build/test
        ↓
OcctNet.Smoke build/run against the real Native DLL + OCCT runtime
```

## 3. Windows 静态 Contract Checks

当前保留 6 个长期仓库不变量检查：

| Script | 责任 |
| --- | --- |
| `tests/check-version-contract.ps1` | Bridge/ABI/OCCT/.NET/CMake/TFM/平台版本契约 |
| `tests/check-architecture-boundaries.ps1` | Managed/Native 领域边界、Interop 归属和 UI/Core 依赖方向 |
| `tests/check-abi5-contract.ps1` | ABI5-only，拒绝 ABI4 文件、Handle、元数据和 Binary SDK 残留 |
| `tests/check-bulk-abi.ps1` | 高基数集合保持 Snapshot/Buffer ABI，拒绝 N+1 indexed ABI 回流 |
| `tests/check-native-build-structure.ps1` | CMake Native source inventory、平台隔离、OCCT 7.9 toolkit 与领域布局 |
| `tests/check-api-surface.ps1` | Native declaration/definition 与 Core `LibraryImport + Cdecl` 精确对等；UI Adapter 不得自行绑定 `occt_*` |

执行：

```powershell
.\build.ps1 validate Release
```

这些脚本只维护长期结构和 ABI 不变量，不替代编译器、Managed Test 或 Native Smoke。

## 4. Managed regression tests

项目：

```text
tests/OcctNet.ManagedTests/OcctNet.ManagedTests.csproj
```

它不需要加载 OCCT Native runtime，主要验证纯 Managed 行为、DTO/Value Type、Owner/Identity、Guard、Transform、Runtime Diagnostics、Viewport Policy 等。

推荐通过统一入口执行：

```powershell
.\build.ps1 test Release
```

`test` 会先构建测试项目，再使用 `--no-build` 执行测试，避免测试阶段隐式改变构建输入。

## 5. Native Smoke

项目：

```text
tests/OcctNet.Smoke/OcctNet.Smoke.csproj
```

Smoke 使用当前构建的 `OcctNative.dll` 和真实 OCCT 7.9.0 runtime，验证只能由真实 Native 执行确认的建模、拓扑、Mesh、交换、Selection/Viewer 关键路径以及 BridgeVersion/ABI 配对。

执行：

```powershell
.\build.ps1 smoke Release -OcctRoot "D:\tools\occt-vc144-64"
```

完整验证时直接使用：

```powershell
.\build.ps1 all Release
```

## 6. .NET SDK 10.0.303 解析与排障

Managed 相关 target（`managed`、`test`、`smoke`、`dist`、`all`）会在真正开始构建前解析一个能够从仓库根目录使用 **10.0.303** 的 `dotnet.exe`。候选来源包括 `DOTNET_ROOT`、Windows x64 Program Files 安装和当前 `PATH`。

成功时会显示类似：

```text
SDK contract:  10.0.303
dotnet:        C:\Program Files\dotnet\dotnet.exe
SDK resolved:  10.0.303
```

如果某个 PATH 中的 `dotnet.exe` 看不到 10.0.303，但标准 x64 安装能看到，脚本会使用可用的 host，而不是在 Native 编译完成后才失败。

手工诊断：

```powershell
& "C:\Program Files\dotnet\dotnet.exe" --list-sdks
& "C:\Program Files\dotnet\dotnet.exe" --version
where.exe dotnet
```

`--list-sdks` 必须包含 `10.0.303`，并且在仓库根目录执行 `--version` 必须返回 `10.0.303`。如果没有，请安装精确 SDK 或修复 `DOTNET_ROOT/PATH`；不要修改 `global.json` 去兼容其它 SDK。

## 7. Linux build.sh

语法：

```bash
./build.sh [target] [configuration]
```

支持 target：

```text
validate
native
managed
test
smoke
avalonia-smoke
dist
clean
all
```

常用命令：

```bash
./build.sh validate Release
./build.sh native Release
./build.sh managed Release
./build.sh test Release
./build.sh smoke Release
./build.sh all Release
./build.sh dist Release
```

Linux `managed` 构建 `OcctNet` 与 `OcctNet.Avalonia`；WinForms/WPF 为 Windows-only。

Linux Avalonia Viewer smoke 需要 X11/XWayland `DISPLAY`：

```bash
./build.sh avalonia-smoke Release
```

普通 `smoke` 是 Headless Modeling/Native Smoke，不要求图形桌面。

## 8. Binary SDK

Windows：

```powershell
.\build.ps1 dist Release
```

输出：

```text
dist/win-x64
```

主要包含：

```text
OcctNative.dll
OcctNet.dll
OcctNet.WinForms.dll
OcctNet.Wpf.dll
OcctNet.Avalonia.dll
bridge-contract.json
bridge-manifest.json
```

Linux：

```bash
./build.sh dist Release
```

输出 `dist/linux-x64`。

Binary SDK Manifest 使用 schema 2 的嵌套 ABI5 元数据：

```json
"nativeAbi": {
  "current": 5,
  "minimumSupported": 5
}
```

旧 flat `nativeAbiVersion` 不允许重新引入。

## 9. 正式 Windows 发布验证

正式发布验证只允许在干净、已同步远端的 `main` 执行：

```powershell
.\publish.ps1 -OcctRoot "D:\tools\occt-vc144-64"
```

`publish.ps1`：

- 校验当前分支必须是 `main`；
- 校验工作区干净并基于最新 `origin/main`；
- 调用 `build.ps1 dist Release`；
- 验证 ABI5 Contract、Manifest、Source Commit 与 SHA-256；
- 保证生成过程没有修改 `dist/win-x64` 之外的文件；
- **不执行** `git add`、Commit 或 Push。

生成结果通过正常受审查的 Git 流程发布。当前流程不使用 GitHub Actions。

## 10. 文档与 API Surface 策略

`docs` 只保留手工维护的架构、使用、构建、部署与设计说明，不再生成或跟踪逐类型/逐函数 API Reference，也不再维护 API 文档生成器。

Native/Managed API 是否完整一致由：

```text
tests/check-api-surface.ps1
```

直接从当前源码声明、定义和 `LibraryImport` 绑定进行验证，因此不需要另一套容易失真的生成式 API 文档或硬编码数量统计。
