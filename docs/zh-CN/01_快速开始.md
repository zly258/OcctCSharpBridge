# 快速开始

OcctCSharpBridge 3.0 Stable 的官方预编译平台是 **Windows x64**。Linux x64 保留 Core/Avalonia 源码构建支持。

## 1. 当前契约

- Bridge：`3.0.0`
- Native ABI：仅 ABI 5
- OCCT：7.9.0 exact
- Binary SDK 最低 TFM：`net8.0` / `net8.0-windows`
- Consumer：.NET 8 / 9 / 10
- WinForms/WPF：Windows
- Avalonia：Windows；Linux 源码构建

## 2. 安装 Windows SDK

Bridge 源码构建与 Consumer SDK 安装分开。

仅编译 Bridge，不修改系统 SDK：

```powershell
.\build.ps1 build Release -OcctRoot "D:\tools\occt-vc144-64"
```

安装/更新经过校验的共享 SDK：

```powershell
.\publish.ps1 -OcctRoot "D:\tools\occt-vc144-64"
```

默认安装目录：

```text
C:\Program Files\OcctCSharpBridge\SDK\3.0\win-x64
  OcctNative.dll
  OcctNet.dll
  OcctNet.WinForms.dll
  OcctNet.Wpf.dll
  OcctNet.Avalonia.dll
  bridge-contract.json
  bridge-manifest.json
```

开发机/构建机可通过 `OCCTCSHARPBRIDGE_SDK` 覆盖 SDK Root。Consumer 仓库不再保存 Windows SDK 同步副本。

## 3. Managed 引用

统一定义 SDK Root：

```xml
<PropertyGroup>
  <OcctBridgeSdkRoot Condition="'$(OCCTCSHARPBRIDGE_SDK)' != ''">$(OCCTCSHARPBRIDGE_SDK)</OcctBridgeSdkRoot>
  <OcctBridgeSdkRoot Condition="'$(OcctBridgeSdkRoot)' == ''">$(ProgramFiles)\OcctCSharpBridge\SDK\3.0\win-x64</OcctBridgeSdkRoot>
</PropertyGroup>
```

按项目需要引用：

```xml
<ItemGroup>
  <Reference Include="OcctNet">
    <HintPath>$(OcctBridgeSdkRoot)\OcctNet.dll</HintPath>
    <Private>true</Private>
  </Reference>
</ItemGroup>
```

需要 UI Adapter 时再增加 `OcctNet.WinForms.dll`、`OcctNet.Wpf.dll` 或 `OcctNet.Avalonia.dll`。

## 4. Runtime 初始化

第一个 Native-backed 调用之前：

```csharp
using OcctNet;

OcctRuntime.Configure();

using var model = new OcctModelingSession();
var box = model.MakeBox(100, 80, 10);
model.ExportStep(box, "box.step");
```

## 5. WPF/Avalonia 首帧

Viewport 正常加入 Visual Tree 即可。启动逻辑如果依赖 Native 首帧已经真正呈现，应等待 `HostState == Ready`。

`Ready` 只会在 Viewport 获得有效布局尺寸，并完成一次 `ResizeSurface + Redraw` 后进入。不要用模拟鼠标移动、固定延时或重复启动 Redraw 来触发第一次显示。

## 6. Linux

Linux 从源码构建：

```bash
./build.sh build Release
```
