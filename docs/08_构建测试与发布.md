# 08 构建测试与发布

`build.ps1` 是仓库统一入口。验证按三层组织：**仓库级静态契约 → Managed 回归 → 真实 Native Smoke**。原则是让每类问题由最可靠的机制验证，而不是用大量 PowerShell 字符串扫描替代编译和测试。

## 1. `bridge-contract.json`

机器可读契约包括：

- Bridge Version；
- Native ABI Version；
- OCCT Version；
- Platform；
- CMake Minimum Version；
- .NET Target Framework；
- .NET SDK Version；
- C# Language Version；
- Native/Managed/Public API 数量。

代码和构建配置需要与 Contract 一致；README/docs 只负责说明，不作为构建配置的第二份来源。

## 2. build target

```powershell
.\build.ps1 validate Release
```

只执行仓库级静态契约，不需要 OCCT SDK。

```powershell
.\build.ps1 managed Release
```

增量构建 `OcctNet`、WinForms/WPF/Avalonia Host。默认保留各项目 `bin/obj`，由 MSBuild 判断是否需要重新编译。

```powershell
.\build.ps1 test Release
```

构建 `OcctNet.ManagedTests` 并通过标准 `dotnet test` 执行 Managed Regression，不加载 OCCT Native Runtime。

```powershell
.\build.ps1 native Release
```

使用 CMake + MSVC + OCCT 7.9.0 构建 `OcctNative.dll`。

```powershell
.\build.ps1 pack Release
```

构建四个 Managed NuGet/Symbol Package，并在打包后直接检查包内程序集、XML、README/LICENSE 以及 Native Runtime 泄漏。

```powershell
.\build.ps1 ci Release
```

构建 Managed SDK、Managed Regression、Smoke Project，并生成/验证 NuGet；该本地目标不要求 OCCT SDK。

```powershell
.\build.ps1 smoke Release
```

构建真实 Native Bridge 并执行 OCCT Smoke。

```powershell
.\build.ps1 clean Release
```

显式删除 `build/`、`artifacts/` 以及各项目 `bin/obj`。仅在需要真正全量重建、切换异常缓存或排查生成文件问题时使用。

```powershell
.\build.ps1 all Release
```

执行默认静态契约后构建 Native + Managed Bridge。

## 3. 默认使用增量构建

过去 `Build-Project` 会在每次 `dotnet build` 之前删除对应项目的 `bin/obj`。这会让 Core 被 WinForms/WPF/Avalonia 等项目引用时反复失去缓存，等价于把正常的增量构建变成多次局部全量构建。

现在默认策略是：

- 日常 `managed` / `all` / `ci` 保留 `bin/obj`；
- 让 MSBuild 根据 Inputs/Outputs 正常进行增量判断；
- `pack` 在已完成构建后继续使用 `--no-build`；
- Managed Test 在测试程序集已构建后使用 `dotnet test --no-build`；
- 真正需要清理时统一执行 `build.ps1 clean`。

## 4. 静态契约已经收敛

当前只保留 6 个脚本：

| Script | 检查范围 |
|---|---|
| `check-version-contract.ps1` | Contract 与 Native/Managed/.NET/CMake 版本和平台 |
| `check-architecture-boundaries.ps1` | Core/UI 依赖方向、main/应用层边界、禁止兼容层 |
| `check-bulk-abi.ps1` | Modeling 高数量集合与 Selection Hit 的 Bulk ABI |
| `check-native-build-structure.ps1` | CMake 源清单、OCCT 7.9 Toolkit、禁止 OCAF/XDE |
| `check-api-surface.ps1` | Native declaration/definition/PInvoke 对等与数量 |
| `check-sdk-package.ps1` | Managed SDK NuGet 元数据 |

### 适合静态检查

- Native export 与 P/Invoke 不对应；
- API 数量偏离 Contract；
- OCAF/XDE 被重新引入；
- Main 出现上层 CAD Application Project；
- Bulk API 被恢复成 N+1 indexed ABI；
- CMake 漏列 `.cpp`；
- NuGet Project Metadata 偏离统一 Target Framework。

### 不再静态扫描的内容

- 方法必须位于指定 partial 文件；
- 某个 `.cpp/.cs` 必须逐字包含某一段实现；
- Runtime/Selection/Geometry 的内部算法写法；
- Smoke Test 文件必须出现某个调用字符串；
- README/docs 必须包含某一固定句子；
- 源文件最大字节数。

这些内容应该由编译、Managed Test、Native Smoke 或代码评审验证。

## 5. Managed 回归

Managed Regression 使用 `MSTest.Sdk`，不加载 OCCT，主要覆盖：

- Value Type / Guard；
- Owner-aware Handle；
- Geometry/Transform Helper；
- Runtime Diagnostics 无副作用；
- Viewport Interaction Policy；
- Native DTO ↔ Managed Result Mapping。

测试采用标准 `[TestClass]` / `[TestMethod]`，由 `dotnet test`、Visual Studio Test Explorer 等正常发现。失败定位到具体 TestMethod，不再通过顶层 EXE Runner 或 `[ModuleInitializer]` 隐式执行。

## 6. Native Smoke

只有真实 OCCT Smoke 才能验证：

- C++ 编译和链接；
- `OcctNative.dll` / OCCT DLL 加载；
- 实际几何和拓扑算法；
- Viewer/Selection Native 行为；
- Mesh 和数据交换；
- ABI Struct 在真实调用中的正确性。

发布前执行：

```powershell
.\build.ps1 smoke Release -OcctRoot "D:\tools\occt-vc144-64"
```

## 7. API 数量不是完整 ABI 校验

`348 Native == 348 P/Invoke` 能发现新增/删除遗漏，但不能发现：

- `double` → `float`；
- 参数顺序变化；
- `int64` → `int32`；
- Struct 字段布局变化；
- Enum 数值变化。

因此后续 ABI 强化应增加签名级检查：Return Type、Parameter Type/Order、Struct `sizeof/offsetof`、Enum Numeric Value。这个方向比继续新增源码字符串 Contract 更有价值。

## 8. 推荐验证顺序

日常开发：

```powershell
.\build.ps1 validate Release
.\build.ps1 managed Release
.\build.ps1 test Release
```

提交前：

```powershell
.\build.ps1 ci Release
```

涉及 Native/ABI/OCCT 或正式发布：

```powershell
.\build.ps1 smoke Release
```

## 9. PowerShell 检查原则

新增静态检查必须同时满足：

1. 属于长期仓库不变量；
2. 编译或运行测试不能更可靠地验证；
3. 正常内部重构不会触发误报；
4. 与已有检查没有重复职责。

否则应优先补 Managed Test、Native Smoke 或 ABI 自动校验，而不是新增 `Contains()` 检查。
