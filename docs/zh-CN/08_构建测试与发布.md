# 构建、测试与发布

Bridge 3 使用同一套 ABI5-only 源码维护 Windows x64 与 Linux x64。`bridge-contract.json` 是 Bridge、ABI、OCCT、.NET 与平台要求的机器可读事实源。

## 1. 环境要求

Windows x64：

- Visual Studio 2022 / MSVC x64 C++ 工具链；
- CMake 不低于 `bridge-contract.json` 声明版本；
- OCCT **7.9.0** x64；
- **.NET SDK 10.0.303 精确版本**；
- C# 14 与 PowerShell。

Linux x64：

- C++17 编译器与 CMake；
- OCCT 7.9.0；
- .NET SDK 10.0.303 精确版本。

根目录 `global.json` 禁止 SDK roll-forward。不要通过降低版本要求或启用 roll-forward 绕过契约。

Windows 默认 OCCT Root：

```text
D:\tools\occt-vc144-64
```

## 2. Windows build.ps1

```powershell
.\build.ps1 [Target] [Configuration] [-OcctRoot <path>]
```

Target：

| Target | 行为 |
| --- | --- |
| `validate` | 仓库静态 Contract Checks |
| `native` | 构建 `OcctNative.dll` |
| `managed` | 构建 Core、WinForms、WPF、Avalonia |
| `test` | 构建并运行 Managed Regression Tests |
| `smoke` | Native + Managed + 真实 Native Smoke |
| `dist` | 生成 Release `dist/win-x64` Binary SDK |
| `clean` | 删除生成输出 |
| `all` | 完整本地验证，不生成 `dist` |

推荐完整验证：

```powershell
.\build.ps1 all Release -OcctRoot "D:\tools\occt-vc144-64"
```

生成 Windows Binary SDK：

```powershell
.\build.ps1 dist Release -OcctRoot "D:\tools\occt-vc144-64"
```

`dist` 要求干净源码树和 Release 配置。

## 3. 静态 Contract Checks

除 `clean` 外的 Windows Target 都先执行仓库长期不变量检查：

| Script | 责任 |
| --- | --- |
| `tests/check-version-contract.ps1` | Bridge/ABI/OCCT/.NET/CMake/TFM/平台契约 |
| `tests/check-architecture-boundaries.ps1` | Native/Managed 与 UI/Core 依赖边界 |
| `tests/check-abi5-contract.ps1` | ABI5-only，拒绝 pre-ABI5 兼容遗留 |
| `tests/check-bulk-abi.ps1` | 高基数集合保持 Snapshot/Buffer ABI |
| `tests/check-native-build-structure.ps1` | Native CMake Inventory 与平台隔离 |
| `tests/check-api-surface.ps1` | Native Declaration/Definition 与 Core `LibraryImport + Cdecl` 精确对等 |

这些检查不替代编译器、Managed Regression Test 或 Native Smoke。

## 4. Managed Regression 与 Native Smoke

Managed-only 回归项目：

```text
tests/OcctNet.ManagedTests/OcctNet.ManagedTests.csproj
```

执行：

```powershell
.\build.ps1 test Release
```

Native Smoke 项目：

```text
tests/OcctNet.Smoke/OcctNet.Smoke.csproj
```

执行：

```powershell
.\build.ps1 smoke Release -OcctRoot "D:\tools\occt-vc144-64"
```

Windows 完整门禁使用 `build.ps1 all Release`。

## 5. 精确 .NET SDK 解析

Managed 相关 Target 会从仓库根目录解析能够使用 **10.0.303 精确版本** 的 `dotnet` Host。正常输出应包含：

```text
SDK contract:  10.0.303
SDK resolved:  10.0.303
```

解析失败时应安装精确 SDK 或修复 `DOTNET_ROOT` / `PATH`，不要修改 `global.json` 去兼容其它 SDK。

## 6. Linux build.sh

```bash
./build.sh [target] [configuration]
```

支持：

```text
validate
native
managed
test
smoke
avalonia-smoke
dist
clean
all
```

常用命令：

```bash
./build.sh validate Release
./build.sh managed Release
./build.sh test Release
./build.sh all Release
./build.sh dist Release
```

Linux `managed` 构建 `OcctNet` 与 `OcctNet.Avalonia`；WinForms/WPF 为 Windows-only。`avalonia-smoke` 需要 X11/XWayland `DISPLAY`；普通 Native Smoke 为 Headless。

## 7. Binary SDK 布局

Windows `dist/win-x64`：

```text
OcctNative.dll
OcctNet.dll
OcctNet.WinForms.dll
OcctNet.Wpf.dll
OcctNet.Avalonia.dll
bridge-contract.json
bridge-manifest.json
```

Linux `dist/linux-x64`：

```text
libOcctNative.so
OcctNet.dll
OcctNet.Avalonia.dll
bridge-contract.json
bridge-manifest.json
```

Binary SDK Manifest 使用 schema 2 的嵌套 ABI5 元数据，并记录精确 `sourceCommit` 与每个 Payload 文件的 SHA-256。旧 flat `nativeAbiVersion` 不允许重新引入。

## 8. Binary SDK 源码管理策略

`dist/win-x64` 与 `dist/linux-x64` 是**生成构建产物，不是源码文件**。仓库只保留 `dist/README.md`；生成的 DLL/SO 包全部由 Git 忽略。

这样可以避免仓库膨胀、源码/二进制不同步与跨平台 Payload 历史污染。Consumer 必须校验 Package Contract、Manifest、Source Commit 与 Hash，而不是通过 Git 历史猜测二进制是否最新。

统一 `demo` 分支遵循同一策略，将 `dist/` 视为可删除的本地缓存。Windows/Linux 同步脚本只有在 `manifest.sourceCommit` 与全部 Hash 匹配选定 `main` Revision 时才复用 Binary SDK。

## 9. 正式分发

Windows 发布验证可在干净、同步远端的 `main` 执行：

```powershell
.\publish.ps1 -OcctRoot "D:\tools\occt-vc144-64"
```

`publish.ps1` 会校验当前 Branch/Source Revision，调用 Release Binary SDK 生成流程，并验证 Contract、Manifest、Source Commit 与 Hash；它**不会**执行 `git add`、Commit 或 Push。

验证通过后，应通过受审查的制品渠道分发，例如 GitHub Release Asset 或其它受控 Package 位置。不要把生成 Binary SDK Payload 提交到 `main`、`main-dev`、`demo`、`demo-dev`。该流程不需要 GitHub Actions。

## 10. Demo Consumer 模型

正式 `demo` / `demo-dev` 是唯一应用 Consumer 线：

- Windows x64：WinForms、WPF、Avalonia；
- Linux x64：仅 Avalonia。

Demo 消费 `main` 生成的 Binary SDK，不得复制 Bridge Native/Core 实现源码，也不得直接声明 `occt_*` ABI。

## 11. 文档与 API Surface 策略

`docs` 只保留手工维护的架构、使用、构建、部署与设计说明，不再生成或跟踪逐类型/逐函数 API Reference，也不再维护 API 文档生成器。

Native/Managed API 是否完整一致由 `tests/check-api-surface.ps1` 直接从当前源码验证，避免第二套生成式文档 Surface 与容易失真的硬编码接口数量。
