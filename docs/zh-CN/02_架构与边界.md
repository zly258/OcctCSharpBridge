# 02 架构与边界

## 分层

```text
应用层
  Document / Feature Tree / Command / Tool / Undo-Redo / Persistence
       │
       ▼
UI Host
  OcctNet.WinForms / OcctNet.Wpf / OcctNet.Avalonia
       │
       ▼
OcctNet
  Viewer + Modeling 托管 API
       │ P/Invoke / stable C ABI 4
       ▼
OcctNative (C++17)
       │
       ▼
Open CASCADE Technology 7.9.0
```

## 所有权

`OcctModelingSession` 管理 Headless Shape 与算法；`OcctEngine` 管理 AIS/Viewer 对象、选择和场景状态。Handle 只在所属 Session/Engine 内有效，不能直接充当业务 EntityId。

推荐通过 `ApplicationTag` 或上层自己的 ID 映射把业务实体与 Viewer 对象关联。

## OCAF/XDE 边界

OcctCSharpBridge 不把 OCAF/XDE 作为上层应用 Document 架构。Feature Tree、Undo/Redo、Command History、项目 JSON 等仍由业务应用实现。

但 STEP 产品结构、Occurrence、颜色、显隐和 Subshape Style 在 OCCT 中天然属于 XDE，因此 Bridge 会在数据交换内部使用 XDE，并通过 `OcctAssemblyDocument` 投影到托管模型，而不是把 `TDocStd_Document` 暴露给应用。

## 分支边界

- `main`：Bridge 与正式 Binary SDK 生产者；
- `demo`：消费本地被忽略的 SDK；
- `website`：静态官网。
